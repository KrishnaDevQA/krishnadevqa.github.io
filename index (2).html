My automation framework

A personal project that shows how I structure test automation: small reusable pieces, configuration kept outside the code, and a result I can read at a glance.

  • Page Object ModelEach page has one class, and tests read like the user journey.
  • Configuration managementURL, browser and timeouts live in a properties file, so nothing is hard-coded.
  • Logging, reports and screenshotsEvery run leaves evidence that explains a failure.
  • TestNG suites on MavenRun one suite or the whole set from the IDE or the command line.
